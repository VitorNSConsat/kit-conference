{{ ic.svg('camera', 18) }} A câmera exige HTTPS

Consultar Kit/Item, Ler RMA, Ler Sobressalentes e a bipagem por câmera só abrem a câmera em HTTPS. Por http:// o navegador bloqueia (aparece o pedido de foto, ou nada).

    {% if publico %}
  • Melhor opção: o endereço público acima (Cloudflare) — HTTPS válido, nada a instalar.
    • {% endif %} {% if tem_ssl %}
  • Na rede interna: use {{ url_https }}. Na primeira vez, baixe e instale o certificado no aparelho: {{ url_http }}/cert (iPhone: Ajustes → Perfil Baixado → Instalar; depois Geral → Sobre → Confiança de Certificado → ativar “KitConference”. Android: abra o arquivo baixado e instale como certificado CA.)
    • {% else %}
  • Sem certs/cert.pem não há HTTPS local. Gere com python gerar_cert.py no servidor e reinicie o serviço, ou use o endereço público.
    • {% endif %}

{{ ic.svg('celular', 18) }} Se um aparelho não abrir

  • Confira que ele está no Wi-Fi da empresa (ou use o endereço público, de qualquer rede).
  • Digite o endereço com http:// na rede interna. Com https:// na porta {{ url_http.rsplit(':', 1)[-1] }} o navegador mostra erro de conexão segura.
  • Tela branca no iPhone em https://…:8011: o serviço precisa estar com o run.py atual e o certificado instalado no aparelho; se o atalho da tela de início ficou preso, apague-o e adicione de novo.

{{ ic.svg('alerta', 18) }} Firewall do Windows

Se nenhum aparelho da rede conseguir acessar, execute como Administrador no CMD:

netsh advfirewall firewall add rule name="Kit Conference" dir=in action=allow protocol=TCP localport={{ url_http.rsplit(':', 1)[-1] }},8011
